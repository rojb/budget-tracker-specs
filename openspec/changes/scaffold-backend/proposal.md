# Proposal

## Why

The two devs need a working `budget-tracker-back` repo before any feature work can start. It
must ship with the team's no-test-files rule already wired in, so no later scaffold or
generator can silently reintroduce `*.spec.ts` files.

## What Changes

- Initialize `budget-tracker-back` with Nest CLI, ESLint/Prettier.
- Set up per-feature module structure (module/controller/service/dto/entities, no hexagonal).
- Add `docker-compose` (Postgres) and initial Prisma setup.
- Set `nest-cli.json` `generateOptions.spec: false`; delete default `*.spec.ts` files and the
  default `/test` folder generated by the CLI.
- CI: lint + build only, no test step.

## Capabilities

### New Capabilities

None — this is repo scaffolding and tooling setup, no application behavior yet.

### Modified Capabilities

None.

## Impact

- Repos touched: `budget-tracker-back`.
- Unblocks: `api-contract-base` (oasdiff wiring), `add-auth`, `add-budget-calc-engine`, and
  every backend module.
